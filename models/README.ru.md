# Добавление модели

[English](README.md) · [Русский](README.ru.md)

Модель не включена. Совместимый бандл поставляется отдельно и выбирается
через `--model DIRECTORY` или `ThreatAnalyzer.from_bundle()`.
Его каталог может находиться за пределами репозитория.

Загрузчик принимает `model-bundle-0.1` с `window_scores_v1` или
`window_scores_v2` и `model-bundle-0.2` с `window_features_v3`.
Версия таксономии, порядок семи меток, max-logit агрегация, параметры окон,
размеры, SHA-256, лицензия и происхождение обучения должны соответствовать
контракту runtime. Версия 3 дополнительно требует `heads.npz` и focus template.
Поддерживаются самостоятельные ONNX-графы; внешние файлы тензоров
отклоняются. Отдельный training checkpoint предварительно экспортируется.

```bash
personal-threats check-model models/approved/bundle --device cpu
python examples/check_installation.py \
  --model models/approved/bundle
```

`check-model` проверяет совместимость графа и конечность выхода,
но не подтверждает точность обнаружения. Обычный анализ отклоняет модели
`test_fixture`, если явно не включён тестовый режим.

Профиль использует `quality-local-report-0.1` и ссылается на точный хеш
манифеста бандла, область оценки, матрицы ошибок, пороги и массивы
оценок/меток/масок. Массивы хранятся рядом с отчётом по путям из `files`.
Загрузчик проверяет хеши и пересчитывает фактические решения
parent-or-types и ограничения precision/FPR.
Для дополнительной проверки предоставленного профиля добавляется
`--profile-report models/approved/profile/report.json` к команде диагностики
после размещения отчёта и указанных в нём массивов в этом каталоге.

Код моделей, веса и датасеты сохраняют собственные лицензии.
